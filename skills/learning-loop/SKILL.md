# 🔄 Learning Loop — 自動學習優化系統

## 目標

建立完整的學習迴圈：**做 → 記 → 學 → 優化 → 做**

```
┌─────────────────────────────────────────────────────────┐
│                    Learning Loop                        │
│                                                         │
│   ┌─────────┐    ┌─────────┐    ┌─────────┐            │
│   │  做任務  │───▶│  記沉澱  │───▶│  學模式  │            │
│   └─────────┘    └─────────┘    └─────────┘            │
│        ▲                            │                   │
│        │            ┌─────────┐     │                   │
│        └────────────│ 優化 SKILL│◀────┘                  │
│                     └─────────┘                         │
└─────────────────────────────────────────────────────────┘
```

## 三大功能

### 1. 任務後自動沉淀（Post-Mortem Auto-Extract）

**觸發時機：** 任務完成後、人類說「學到什麼」、「回顧一下」

**流程：**

1. **讀取 work/history** — 找到最近完成的任務
2. **提取學習點** — 分析：
   - 做了什麼決定？為什麼？
   - 遇到什麼問題？怎麼解決的？
   - 有沒有更好的做法？
   - 這個經驗可以套用到哪裡？
3. **更新 wiki** — 把學習點寫入相關 entity/concept 頁面
4. **更新花園** — 如果有新的 insights，灌溉對應的種子
5. **記錄到 learning journal** — 寫入 `work/learning/YYYY-MM.md`

**輸出格式：**

```markdown
## [任務名稱] — 學習沉淀

### 決策記錄
| 決策 | 理由 | 結果 | 學到什麼 |
|------|------|------|----------|

### 問題與解決
| 問題 | 解法 | 預防措施 |
|------|------|----------|

### 可以做得更好
- [ ] 改進點 1
- [ ] 改進點 2

### 連結到
- [[wiki/entities/xxx|相關 entity]]
- [[wiki/concepts/xxx|相關 concept]]
```

---

### 2. 工作模式分析（Pattern Analysis）

**觸發時機：** 人類說「分析模式」、「找出瓶頸」、「我都在做什麼」

**流程：**

1. **讀取 work/history** — 收集過去 N 天/週的記錄
2. **分類任務** — 按類型分組：
   - 🔬 研究類
   - 🛠️ 實作類
   - 📝 筆記/整理類
   - 🤝 溝通/協作類
3. **分析模式** — 找出：
   - 時間分配比例
   - 重複出現的任務類型
   - 常見的阻塞點
   - 高產出 vs 低產出的活動
4. **產出洞察** — 生成分析報告
5. **建議優化** — 基於分析結果提出具體建議

**分析維度：**

| 維度 | 指標 | 來源 |
|------|------|------|
| 時間分配 | 各類任務花多少時間 | history 事件時間戳 |
| 產出比率 | 完成數 / 開始數 | current.md 統計 |
| 阻塞模式 | blockedBy 重複出現的 ID | current.md |
| 學習密度 | 每個任務提取了幾個 learning | learning journal |
| Skill 使用率 | 各 skill 被調用次數 | skill 執行記錄 |

**輸出格式：**

```markdown
# 工作模式分析 — YYYY-MM-DD ~ YYYY-MM-DD

## 時間分配
| 類型 | 佔比 | 任務數 | 平均耗時 |
|------|------|--------|----------|

## 重複模式
- [模式描述] — 出現 N 次

## 瓶頸點
- [瓶頸描述] — 影響 N 個任務

## 建議
1. [具體建議] — 預期效果
2. [具體建議] — 預期效果
```

### 3. Skill 自我優化（Skill Self-Optimization）

**觸發時機：** 人類說「優化 skill」、「skill 效果如何」、「哪些 skill 該改」

**流程：**

1. **盤點所有 skill** — 讀取 `~/.agents/skills/` 目錄
2. **分析使用記錄** — 找出：
   - 每個 skill 的使用頻率
   - 成功率（完成 vs 失敗）
   - 人類滿意度（如果有 feedback）
3. **識別問題** — 找出：
   - 從未使用過的 skill
   - 使用但效果不佳的 skill
   - 重複功能的 skill
4. **建議改進** — 針對每個問題提出：
   - 合併建議（功能重複）
   - 優化建議（效果不佳）
   - 淘汰建議（從未使用）
5. **執行優化** — 人類確認後，執行改進

**Skill 健康度指標：**

| 指標 | 計算方式 | 健康範圍 |
|------|----------|----------|
| 使用頻率 | 次數 / 天數 | > 0.1（每 10 天至少用一次） |
| 成功率 | 成功次數 / 總次數 | > 0.8 |
| 最近活躍 | 最後使用距今天數 | < 30 天 |

**優化決策樹：**

```
使用頻率 < 0.05？
├── 是 → 考慮淘汰或合併
└── 否 → 繼續觀察
    │
    成功率 < 0.7？
    ├── 是 → 需要優化 SKILL 內容
    └── 否 → 繼續觀察
        │
        最近活躍 > 90 天？
        ├── 是 → 確認是否仍有需求
        └── 否 → 健康
```

## 自動化流程

### 任務完成後自動觸發

當 `work-tracker` 標記任務為 completed 時：

1. 讀取該任務的 refs 和結果
2. 提取學習點
3. 寫入 learning journal
4. 更新相關 wiki 頁面
5. 如有新 insights，更新花園

### 週期性分析

每週一自動執行（可搭配 cron）：

1. 分析過去一週的 work history
2. 產出模式分析報告
3. 識別需要優化的 skill
4. 產出建議清單

## 整合點

### 與 work-tracker 整合

- 任務完成時自動觸發 post-mortem
- 從 task metadata 提取學習點

### 與 wiki-knowledge 整合

- 學習點自動寫入 wiki entity/concept
- 更新相關的 cross-references

### 與 knowledge-garden 整合

- 新 insights 灌溉對應的種子
- 成長階段自動升級（如果有足夠的學習）

### 與 skill-creator 整合

- Skill 優化建議自動傳達給 skill-creator
- 追蹤 skill 改進的效果

## 注意事項

1. **不要過度記錄** — 只記錄有價值的學習，不要為了記錄而記錄
2. **連結比內容重要** — 學習點要連結到 wiki，不要重複寫一遍
3. **定期清理** — 學習 journal 超過 3 個月可以歸檔或刪除
4. **人類主導優化** — Skill 優化建議要人類確認後才執行
