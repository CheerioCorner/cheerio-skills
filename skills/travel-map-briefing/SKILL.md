# Travel Map Briefing

把某趟旅程的既有資料整合成離線行前包（Markdown/PDF）＋地圖匯入 CSV。**只讀不寫。**

## 何時改用其他 skill
- 動線還沒排 → 先用 `travel-map-route`
- 內容還沒查證（飲食適配還是待確認、營業時間沒查）→ 先用 `travel-map-page-content` 補齊，行前包只是把既有資料整合排版，不會幫忙查證
- 要「修改」行程項目本身 → `travel-map-trip-planner`

## 開工前必讀

`travel-map-query/schemas/travel_map_schema.yaml` —— 各欄位位置。

`assets/briefing-template.md`（本 skill 目錄下）—— 行前包的骨架，不要憑記憶重打，段落順序與標題以這份為準。

`assets/my-maps-import-example.csv` —— CSV 欄位格式範例。

## 流程

### 1. 確認範圍
1. 確認是哪趟旅程，用 `travel-map-query` 讀該旅程的 `目的地`、`日期區間`、`同行者組合`
2. 讀該旅程底下所有 `狀態`＝已預訂／已完成 的 `行程項目`，依 `日期時間` 排序（`💡候選`／`⏳待確認` 的不放進行前包——還沒定案的東西不該印出來帶著走，除非使用者明確要求連候選都列）
3. 對每個行程項目讀 `相關見聞錄` 的完整正文（不只 Properties）：地址、座標、當地語言名稱、飲食適配、點餐關鍵字、背景故事、購票怎麼開口

### 2. 讀地方誌層級的內容
對這趟涉及的每個地方誌條目，讀正文的：`🚗 自駕實務`、`🗣️ 語言功課`、`🎫 票券與套票`、`🏛️ 歷史脈絡速讀`。這幾節是 Cheer 在台灣做的語言/自駕功課，行前包**必須完整帶入**，不要摘要到看不出重點——現場沒網路時這是唯一能查的地方。

### 3. 產出行前包
1. 依 `assets/briefing-template.md` 骨架整合，逐日行程用表格列清楚：時間、地點（含當地語言原文）、地址、座標、備註
2. 餐廳的飲食適配速查表要看得出「這間誰能吃、誰不適合」，不要只寫「飲食適配：✅」這種代碼，要寫白話結論
3. 「🆘 緊急資訊」一節裡信用卡掛失電話、保單號這類欄位，系統目前沒有存這些資料，**留空並標註「使用者自行補」**，不要留白也不要瞎編
4. 檔案命名：`[旅程名稱]-行前包.md`，寫入工作目錄後用 SendUserFile 交付給使用者
5. 如果使用者要 PDF 版本，改用 `pdf` skill 把這份 markdown 轉成 PDF 再交付，不要自己手刻 PDF 排版

### 4. 產出地圖 CSV
1. 撈這趟所有有 `座標` 的見聞錄，輸出 `name,lat,lng,category,note` 格式的 CSV（`category` 用 `類別`，`note` 可放 `標籤` 或行程備註）
2. 檔案命名：`[旅程名稱]-地圖.csv`，一樣用 SendUserFile 交付
3. 沒有座標的項目列在行前包裡的一個小提醒段落，告訴使用者這幾個沒進地圖

## 規則
- **不查證，只整合既有資料**。查到「未查證」就照樣標「未查證」放進行前包，不要因為要交付一份好看的文件就把不確定的東西寫得肯定
- 只收「已預訂／已完成」狀態的行程項目，候選/待確認的不放（除非使用者明確要求）
- 緊急資訊類系統沒存的欄位，留空並註明由使用者自己補，不要編造
- 行前包產出後如果旅程資料又有異動，重新整份產生，不要手動局部修改舊檔案
