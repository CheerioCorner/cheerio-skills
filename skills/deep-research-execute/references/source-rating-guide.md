# 來源品質判準（Quality Filter Criteria）

這份文件定義 `scripts/quality_filter.js` 丟給 Gemini Notebook 的 prompt 裡要求它判斷的移除條件。判斷本身交給 Gemini Notebook 執行（它能實際讀到來源內容），本檔案只是把判準寫清楚、固定下來，避免每次呼叫措辭不一致。

## 應移除的來源類型

1. **廣告／宣傳／行銷頁面**：產品功能介紹首頁、展示或畫冊頁面（僅圖片/截圖/高階概念，無技術細節）、銷售/定價/方案比較頁、純推廣性質的 adoption pitch（除非包含具體部署參數或實作步驟）。
2. **膚淺心得文**：一味稱讚或一味批判、沒有具體論據或技術細節支撐的評論文章；簡短、無結論、無代碼、無明確解法的社群問答串。
3. **過期資訊**：內容明顯針對已停產/已下架的產品或版本、與 `research_profile.timeframe` 設定的時間範圍明顯不符、或內容本身已被後續更新的資訊取代。

**重要原則**：即使是官方網域，若頁面本身缺乏實質技術深度（例如官網行銷頁），一樣要列入移除，不能因為網域名稱就自動視為高品質。

## 保留原則

不符合上述任一移除條件的來源都保留，不做額外的人工分級（must_include/should_include/reference 這套三級分類已經被取消——過去是靠本地關鍵字比對粗略分級，現在改成直接讓 Gemini Notebook 讀內容判斷「該不該留」，不再需要中間分級）。

## 使用方式

`quality_filter.js` 組 prompt 時直接引用「應移除的來源類型」三條，要求 Gemini 針對 `nlm list sources` 目前列出的每一筆來源逐一檢查，回傳 JSON 格式的移除清單（見 SKILL.md 品質過濾步驟說明）。
