# Travel Map Trip Feedback

旅程完成後的回饋迴圈：行程項目 → 見聞錄／地方誌。**這是整套系統裡最容易被忽略、
但最關鍵的一步**——沒有這一步，地方誌/見聞錄永遠停在「蒐集中」，系統就長不大。

## 何時改用其他 skill
- 只是要「新增/修改」旅程或行程項目 → `travel-map-trip-planner`
- 只是要「新增/修改」地方誌或見聞錄 → `travel-map-knowledge-capture`
- 只是要「查」資料 → `travel-map-query`

## 開工前必讀

`travel-map-query/schemas/travel_map_schema.yaml`（另一個 skill 目錄下）。

## 流程

1. 用 `travel-map-query` 讀這趟旅程底下所有已完成的行程項目，以及旅程頁面的「回顧心得」欄位（視為草稿來源，先讀這裡再分流，不用重新問使用者一次）
2. **分流判斷**，把心得依性質寫回：
   - 具體店家/景點的評價（好不好吃、好不好玩）→ 對應**見聞錄**頁面的「✅ 親身驗證心得」區
   - 國家/區域級的知識（簽證流程、當地習俗、整體交通眉角）→ 對應**地方誌**頁面的「✅ 親身驗證心得」區
3. 呼叫 `travel-map-page-content` 的內容格式規則寫入——**是累加，不是整合覆蓋**：每次用日期開新的一段，不要動之前的心得
4. **針對每個造訪過的見聞錄問一次 `喜愛度`**（1～5 星）。這一欄以前沒有任何 skill 負責、永遠空白——它空著整個系統就排不出「值得再去」的清單，所以不要跳過，一次列出來讓使用者一起回答
5. 調整 `成熟度`（規則見 schema 的 `maturity_rules`）：
   - 🌱 → 🌿：實際造訪過就升
   - 🌿 → 🌳：**不自動升**。要造訪 2 次以上，而且使用者明確說「這裡我熟」才給
6. 有買紀念品的話，把實際戰利品累加進地方誌的「🛍️ 想帶回家」一節（買了什麼、哪裡買、多少錢、值不值得），下次去同一國直接有清單
7. 「最後更新」改成今天

## 規則
- 心得的事實本身來自使用者真實經歷，**不是查證來的資料**——本 skill 只負責整理措辭、分流寫回、更新屬性，不對心得內容做查證或補充（那是 `travel-map-page-content` 對「蒐集資料」區的職責，跟這裡的「親身驗證心得」區不同）
- 不確定某段心得該歸見聞錄還是地方誌時，寧可問使用者一句，也不要亂分流
- 找不到對應的見聞錄/地方誌頁面時，先用 `travel-map-knowledge-capture` 建立，再回來寫心得

## 相關 Skills
- `travel-map-query` — 查詢既有資料
- `travel-map-trip-planner` — 旅程與行程項目的寫入
- `travel-map-knowledge-capture` — 地方誌與見聞錄的寫入
- `travel-map-page-content` — 頁面內容查證與撰寫（心得的段落格式規則）
- `travel-map-briefing` — 下一趟出發前可以把這次的心得一併整合進行前包
