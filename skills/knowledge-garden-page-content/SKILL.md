# Knowledge Garden Page Content

根據標的物類型，產出一份**有觀點的專屬報告**。

## ⚠️ 核心理念

**不是套模板，而是針對這個題目產出報告。**

每份 content 都是：
- 客觀事實（從來源提取）
- 主觀現實（人的決策、想法、判斷）
- Roadmap（下一步延伸）

**不要只讀 Properties 就產內容。** 必須先收集資料。

---

## 四層通用骨架

所有標的物都用同一個結構：

| 層 | 內容 | 說明 |
|----|------|------|
| 第一層 | 標的識別與中繼資料 | 類型、階段、標籤、關聯 |
| 第二層 | 客觀事實層 | 定義、規格、參考資料 |
| 第三層 | 主觀現實層 | 個人經驗、決策脈絡、思維模型 |
| 第四層 | 延伸路線圖 | 下一步行動、未解問題 |

**成長階段（🌱/🌿/🌳）只是成熟度狀態屬性，不決定內容結構。**

---

## Mode 切換

根據使用者輸入自動判斷：

| 條件 | 模式 | 說明 |
|------|------|------|
| 輸入 < 30 字、純名詞 | Quick Draft | 極簡生成，跳過研究步驟 |
| 包含 URL、附件、或「深入/分析/比較」 | Enriched | 完整研究流程 |
| 使用者說「草稿」「快速」 | Quick Draft | 顯式指定 |
| 使用者說「深入」「研究」 | Enriched | 顯式指定 |

---

## Phase 0：研究（Enriched 模式才做）

### Step 1：讀取 Properties

```
notionApi_API-retrieve-a-page → 取得所有 Properties
```

### Step 2：Fetch 來源 URL（如有）

```
web_fetch({ url: "<來源 URL>" })
```

提取：核心論點、關鍵數據、技術細節、與我們做法的異同。

Fetch 失敗時跳過，但仍繼續。

### Step 3：讀取 Wiki 頁面（如有）

```
read({ path: "C:/Cheerio/Obsidian/<wiki-path>" })
```

提取：已有知識點、交叉引用、既有結論。

### Step 4：查詢相關種子/專題（可選）

查詢關聯的種子或專題，用來豐富上下文。

### 研究專題（Research Topic）— 理解到什麼程度、哪些問題沒解

**四層骨架：**
- 第一層：問題定義（Why）— 研究問題、範圍界定、研究動機
- 第二層：已知地圖（What we know）— 種子貢獻、比較分析、客觀事實
- 第三層：主觀判斷（What I think）— 假說驗證、架構抉擇、盲區警示
- 第四層：前線地圖（What s next）— 暫定結論、下一步行動、延伸種子

**注意：每層的內容因專題而異，不是每個專題都長得一樣。**

```markdown
# 🔬 [專題名稱]

> **狀態：** 📋 立案 / 🔬 研究 / 📚 結案

> **最後更新：** [日期]
```

## Phase 2：品質關卡

寫入 Notion 前，執行自我評估：

### Pass 1：初稿生成
根據標的物類型產出內容。

### Pass 2：品質審查
- [ ] 是否有明確的定義和標題？
- [ ] 客觀事實表格是否有實質內容？
- [ ] 主觀觀點是否有深度（不是空話）？
- [ ] 下一步是否具體可執行？
- [ ] 交叉引用是否正確？

### Pass 3：診斷報告（僅 enriched 模式）

> [!NOTE] 💡 **品質診斷**
> - 客觀事實覆蓋率：X/5
> - 主觀觀點深度：X/5
> - Roadmap 具體性：X/5

---

## Phase 3：寫入 Notion

1. **讀取現有頁面**（避免覆寫人類手動寫的）
2. **比較新舊內容**：替換 or 補充 or 標記衝突
3. **寫入**：`ntn pages update <page-id> --content '<markdown>'`
4. **更新 Sync Status**

## 使用範例

### 範例 1：幫 Plannotator 種子寫內容

```
使用者：幫 Plannotator 種子寫內容

→ 讀 Properties：🌿 成長期、來源 URL、Wiki Path
→ Fetch GitHub README
→ 讀 wiki/entities/plannotator.md
→ 產出：
  - 這是什麼：AI coding agent 的視覺化審閱工具
  - 客觀事實：Shared Event API、Multi-Agent、Extension 架構
  - 我的觀點：跟 code-review skill 互補，不是替代
  - 下一步：測試 pi-plannotator-auto extension
→ 寫入 Notion
```

### 範例 2：更新 AI Agent 架構研究專題

```
使用者：更新 AI Agent 架構研究的專題報告

→ 讀專題 Properties：🔬 研究、研究問題
→ 查詢相關種子：Plannotator, Omnigent, mattpocock, OpenCodeReview
→ 產出：
  - 研究問題：如何設計模組化的 AI Agent 架構？
  - 種子地圖：4 顆種子的貢獻
  - 我的判斷：目前假說、架構抉擇
  - 未知：containerization 方案待比較
  - 下一步：Pi vs Docker vs OpenShell 比較
→ 寫入 Notion
```

---

## 注意事項

- **不要只讀 Properties 就產內容** — 必須先研究
- **不要覆寫人類手動寫的內容** — 先讀取現有內容
- **每次寫入後** — 更新 Sync Status
- **主觀觀點是最重要的部分** — 不要怕表達立場
